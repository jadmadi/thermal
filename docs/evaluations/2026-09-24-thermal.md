# Thermal evaluation — 2026-09-24

Thermal has a useful foundation: broad local-tool ingestion, canonical token categories, shared report aggregators, bounded Codex scanning, and a substantial CLI/TUI test suite. The next investment should be correctness and confidence in the numbers, followed by measured ingestion performance. Additional commands would increase maintenance before these contracts are reliable.

## Prioritized findings

### P1 — Receipts can invent successful verification

`internal/thermal/receipt.go:123-145` defaults unknown command outcomes to success and checks pass text before fail text. Pending commands at EOF are assigned exit zero in Claude and Agy parsers (lines 607 and 753). Result matching uses a single active command rather than invocation identity.

A synthetic Claude transcript containing a Bash test invocation and **no result** produced `VERIFIED`. An unknown exit with `1 passed, 2 failed` also produced `go test (exit 0)`. This defeats the central promise of a factual work receipt. Goal: [receipt-evidence-integrity](../../goals/receipt-evidence-integrity/goal.md).

### P1 — Receipt spend and source coverage are misleading

One Agy activity-only transcript produced **500 invented tokens**, from `steps * 500` at `receipt.go:770-780`. The normal loader and report distinguish activity from tokens. Claude receipt parsing loses disjoint categories before pricing and does not apply the loader's message deduplication. The CLI only adds aggregate fallback rows if the entire receipt list is empty (`main.go:1630`), so a Claude receipt can hide unsupported-tool spend. Fallback rows also say CLAIMED without observing an agent claim.

Remove invented usage, retain category/model fidelity, normalize aliases, and explicitly disclose aggregate-only or unavailable receipt coverage. Goal: [receipt-accounting-coverage](../../goals/receipt-accounting-coverage/goal.md).

### P1 — Web and live metrics diverge from static reports

For the same fixture containing Claude's 150 tokens plus one Agy step, web collection reported **151 tokens** and canonical stats reported **150**. Web collection separately sums summaries and rows (`internal/server/server.go:272-421`). It estimates cost only when the entire tool's recorded cost is zero, omitting estimates for unpriced days in a mixed-cost tool. `runServe` passes only Offline into collection, so accepted tool/window/no-estimate settings cannot affect that path.

The live probe converted seven activity steps into `todayTokens=7`. Live cache-hit calculation includes cache writes in the numerator; completed-turn deltas use session counts (`internal/thermal/live.go:146-175,240-252`). Correct these through canonical metrics and fixed-clock parity tests. Goals: [web-telemetry-parity](../../goals/web-telemetry-parity/goal.md), then [live-metric-parity](../../goals/live-metric-parity/goal.md).

### P1 — Devin cache can return another database's usage

The cache has a single path and validates only maximum message row ID and visible session count (`internal/loaders/cache.go:17-40`; `sqlite.go:535-545`). Two synthetic databases with matching probe counts but **100 and 900 tokens** loaded sequentially as **100 and 100**.

Bind the snapshot to source identity; also invalidate edits, replacements, visibility changes and other relevant metadata. Make cache publication atomic. Goal: [devin-cache-source-isolation](../../goals/devin-cache-source-isolation/goal.md).

### P1 — Local telemetry lacks an authority check

A request with `Host: untrusted.example` to the loopback server's handler returned HTTP **200** with synthetic telemetry. Security middleware sets headers but does not validate Host (`internal/server/server.go:84-110`). This is a reproduced missing request boundary; a browser exploit was not tested.

Go's documentation recommends checking request authority to protect against DNS rebinding. The implementation should validate `Request.Host`, including IPv6/ports, before collecting or returning data, while preserving explicitly configured host access. See [Go net/http Request](https://pkg.go.dev/net/http#Request). Goal: [localhost-request-boundary](../../goals/localhost-request-boundary/goal.md).

### P2 — Passing gates do not establish semantic correctness

The current simulated gate passed **95/95 checks** despite the above reproduced failures. Its checks primarily inspect exit codes, formatting and JSON parseability. It conditionally uses the host's real data, merges stderr into stdout for many checks, and does not assert static/web/live parity.

The full race suite failed two color tests under inherited NO_COLOR; both passed on focused rerun with NO_COLOR unset. Server route tests also call real local collection. The goal is reliable fixtures and semantic assertions, not weakening color behavior or hiding failures. Goal: [hermetic-verification-gates](../../goals/hermetic-verification-gates/goal.md).

### P2 — The warm performance target lacks end-to-end evidence

Only model-name and leaderboard benchmarks were found. The `LoadOrScanWithCache` mechanism referenced by AGENTS.md does not exist under internal/. Codex's bounded pool still scans every eligible rollout from the start on each load (`codex.go:156-185,349+`). OpenCode/MiMoCode also run full aggregations.

The documented sub-10ms cached invocation target is **unverified in this evaluation**, not measured and failed. Establish representative cold/warm/changed-input baselines first, then implement a targeted Codex cache preserving exact results. Re-rank other loader optimizations from those measurements. Goals: [ingestion-performance-baseline](../../goals/ingestion-performance-baseline/goal.md), then [codex-incremental-rollout-cache](../../goals/codex-incremental-rollout-cache/goal.md).

## Boundaries and deferred work

Keep the existing terminal-first, read-only architecture. No new hosted telemetry, background daemon, event store, broad cache framework or additional command is proposed. Preserve shared aggregation rather than creating another analytics layer. Fixes changing CLI semantics, JSON keys or token aggregation need the six-part MIGRATION.md entry.

Defer caches for other loaders until representative benchmarks identify their cost. Receipt adapters for additional tools should follow truthful coverage disclosure. Long-lived SSE timeout behavior, receipt scanner memory bounds, yield interpretation, complete loader timestamp/schema compatibility and a visual review remain follow-up review areas; they were not exhaustively verified here.
